# M1 小改：让固餐和液餐有不同的胃排空

**状态：** 固／液差异已实现，不新增 Agent 参数。`npm test` 144/144，白水与可乐重放不变；隔离 DSH 中已核对插件装载及 HTTP 固餐动作入队、同 ID 重试。完整 M1 实机验收（真实双会话工具与通知等）仍待完成。

## 范围与取舍

同体积、同热量、同摄入时长的固餐和液餐不再得到同一条排空曲线。只改胃动力单写者 `stomach/motility.ts` 及其参数、证据和相关文档；`drink`、`eat`、`mealKind` 输入和 `body_act` / `body_state` 工具定义不变。不接睡眠、运动、消化酶、肠道反馈或会话绑定。

- **选用：** 同一个胃脚本分别给已进入胃的固餐和其余内容物记账，再汇总排出量。用两个固定大小的固餐小计即可，不按每份餐扩张已入胃的列表。
- **不选：** 按最近一次 `mealKind` 调整整个胃的速率。喝下一口水不应把还在胃里的固餐改按液餐排空。
- **顺延：** 拆分一份 `mixed` 餐的固液组成、研磨和显式滞后。现有输入没有固液占比；阶段模型也比这次小改需要更多参数。

## 行为和存档

- 保留 `stomach.volumeMl`、`energyKcal` 为轮末总量；`emptiedMl`、`emptiedKcal` 为本轮排出的合计。新增同一部位的 `solidVolumeMl`（mL）和 `solidEnergyKcal`（kcal），均为 `absolute`，分别是总量中已入胃的固餐小计，初值 0，读取总量时不要把小计再加一遍。它们是固定大小的记账字段，不是新的工具参数；查询完整 `stomach` 原始状态时可见，按 `interoception` 查不增加输出。
- 每轮从同一轮初快照出发。原总量减固餐小计是原算法组：仍用能量密度决定半时，保留原液体残余偏置。固餐小计按自身固定半时做一阶排空（本轮比例 `1 − 2^(−dtMin / solidHalfTimeMin)`，不设另一个残余偏置）；体积和能量按同一比例扣减。两组在模型内互不改变对方的速率。
- 仍然先结算当轮排空，再将摄入切片加到账本。仅 `eat` 的 `mealKind: "solid"` 进固餐小计；`drink`、`liquid`、`mixed` 仍走原算法。`mealQueue` 继续只保存待释放量；同一个动作只登记一次，排空与摄入都随原子快照提交。胃充盈、十二指肠暴露和体感继续读取原来的总量或合计通量，不改读者。
- 旧存档缺少固餐小计时由 [Gateway 的初值合并](../../../gateway/simulation.js#L239-L255) 补 0。已入胃的存量保留并走原算法，不猜历史餐型；已有队列尚未释放的切片继续按其 `mealKind` 入账。不开启清空存档或新版本迁移，不改动作时钟。

## 参数与证据

胃动力脚本的固餐时间尺度写入 `motility.parameters.json`：`stomach.emptying.solidHalfTimeMin`，单位 `min`，参考默认值 `68.7`，状态 `design`，范围 `[1, 240]` 是工程调参范围，不是人体百分位。来源登记为 `SRC-VASAVID-2014`；与参数一起更新共享证据台账、脚本头部和胃 README。

[Vasavid 2014 证据笔记](../../../organs/human-organs/stomach/references/notes/vasavid-2014.md) 记录的是健康成人米饭鸡蛋标准餐的标记固相半排空时间。不能把残留百分比换成胃内 mL 或 kcal，也不能说任何固餐必定比任何液餐慢。将这个参考时间用在一阶排空和模拟账本，是工程简化；本轮不复现论文报告的早期滞后和完整曲线。

## 验收

1. 同一起点各提交一次 300 mL、200 kcal 的固餐和液餐（餐型以外完全相同），回执仍为 `queued` 后才生效；摄入提交后 30 个排空轮次，固餐组剩余体积与能量更高。用真实 Gateway 的提交和状态接口对照，离线重放作为补充。
2. 白水和可乐重放的原有观测值和一轮动作延迟不变；交错固餐、液餐和多轮摄入时，胃内存量、待释放量和累计排出量分别守恒（mL 与 kcal）。旧存档加载不会重置报告值，也不会把既有存量猜测为固体。
3. 实现后运行一次 `npm test`，并把当前行为同步到 `organs/human-organs/stomach/README.md` 与相关现状说明。保持 `body_act` / `body_state` 不变，不把固餐验收当成双会话通知或 M1 实机验收通过。

脚本、参数、台账与验证改动走 Tower mission 或 swarm；先完成本小改，再继续原定 M1 实机验收。
