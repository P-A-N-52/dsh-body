# 口渴提醒薄切片设计

**状态：** 已实现并完成离线验收（2026-11-23）。用户已明确可以并行制作多个器官/功能薄切片；本设计复用现有通知策略，不新建器官。最终验证与未验收边界见 [`2026-11-23-parallel-organ-slices.md`](../plans/2026-11-23-parallel-organ-slices.md)。

## 1. 目标与边界

把已有信号接入提醒：

```text
bodyFluid.waterDeficit
  → hypothalamusThirst.thirst
  → interoception.thirst
  → brainNotify
  → 会话决定是否显式 drink
```

只修改提醒策略、参数、测试和文档，不改水链、工具 schema、饮水动作或通知载荷。`drink` 仍由会话显式提交，不自动喝水。

- 65 mm 发 `context`，85 mm 发 `wake`，均为 `design` / `policy`，不是人体口渴阈值。
- 每会话 `levels` 增加独立 `thirst` 水位，仍只存 0/2/3；共享 `resetBelow=40`、45 min 冷却、每小时 2 次、每天 6 次。
- 合格候选先取最高档，同档顺序为 `urinary > thirst > fullness > hunger`，每轮最多一条；未选中的信号不消耗水位。
- `discomfort` 不接入通知，不扩展疼痛、疾病或临床预警。

## 2. 方案取舍

### 选择：扩展现有四类信号策略

在现有 `Kind`、`SIGNAL_ORDER`、`TEXTS`、观测和每会话水位中增加 `thirst`，复用档位、滞回、冷却和配额。代码量小，行为与既有提醒一致。

### 不采用

- **单独口渴通知脚本：** 会复制冷却、配额和会话状态，破坏统一提醒策略。
- **沿用尿意的“动作后抑制”分支：** 饮水不会像排尿一样立即清空口渴；饮水需要经胃和小肠吸收改变体液后才下降，不应在动作轮强制归零。
- **改阈值去迎合特定饮水场景：** 65/85 是统一提醒 policy，不是从单个水量反推的人体标定。
- **同时接入 `discomfort`：** 它是多项感受最大值的聚合，接入会失去具体原因并扩大范围。

## 3. 输入、文本与迁移

`interoception.thirst` 是 0–100 mm 代理，不是血浆渗透压或实测 VAS。缺失/非有限读数在提醒策略中按 50 mm 处理，因此不提醒；该缺省只用于通知门控，不参与水账或生理计算。

固定文本：

```text
明显：身体感受：有些口渴。
强：  身体感受：很口渴。
```

不带水量、诊断或“必须喝水”的指令。

新增参数：

| 参数 ID | 值 | 单位 | 状态 | 来源 |
| --- | ---: | --- | --- | --- |
| `brainNotify.thirst.marked` | 65 | `mm` | `design` / `policy` | `null` |
| `brainNotify.thirst.strong` | 85 | `mm` | `design` / `policy` | `null` |

旧会话已有 `levels` 对象时，缺失的 `levels.thirst` 补 0，其他信号水位不变；更旧会话仍按 `lastKind/lastLevel` 惰性迁移。`lastKind` 允许 `thirst`，`lastLevel` 继续承担下降闩锁和迁移，不升 schemaVersion。

## 4. 轮次与饮水后回落

预置一致的体液状态 `waterVolumeMl = 29650`、`waterDeficit = 0.7` 时，下丘脑目标口渴为 85 mm。两个字段一起预置是为了把验收焦点放在下丘脑→体感→通知，不额外插入体液读数的一轮延迟；若只预置水量并让 `waterDeficit` 从默认值 0 开始，提醒会再晚一轮。由于所有模块只读轮初快照：

1. 第 1 轮下丘脑写 85；体感仍读旧下丘脑 50，通知不发送。
2. 第 2 轮体感写 85；通知仍读旧体感 50，不发送。
3. 第 3 轮通知读到 85，发送一条 `wake`。

口渴提醒相对轮初体液变化为三轮，不能照搬尿意两轮断言。会话未绑定时不产生通知。

显式 `drink` 后：水依次进入胃、小肠和体液，口渴随轮初亏缺下降；不自动喝水、不立即清零、不补发同档提醒。冷却与配额始终共享，其他信号仍可被选中。

## 5. 验收

1. **单元：** 64 不提醒、65 `context`、85 `wake`；同档不重复；观测降到已提醒档以下时水位回落（40–64 mm 按 0），之后升档可再次提醒；与尿意/饱满/饥饿的优先级和最高档规则；旧水位迁移、缺读回退、JSON-safe。
2. **真实 Gateway：** 预置 29650 mL 体液并绑定会话，第 1/2 轮无通知，第 3 轮一条强口渴 `wake`；不自动饮水。
3. **显式饮水：** 提交 `drink` 后跑足够轮次，体液水和口渴按既有水链回落，不出现同档重复提醒；水账仍满足既有 `1e-6 mL` 恒等式。
4. **回归：** 尿意、饥饿、饱满的阈值、滞回、共享冷却和配额不变；完整 `npm test` 与 `git diff --check`。
5. **边界：** 真实 DSH 投递/ACK、重启补算通知和人体口渴阈值验证不在本轮。
