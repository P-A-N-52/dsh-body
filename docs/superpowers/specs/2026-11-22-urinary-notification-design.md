# 尿意提醒与主动排尿闭环设计

**状态：** 当前实现已完成离线单元与真实 Gateway 集成验证；真实 DSH 会话验收尚未完成。用户已授权按推荐方向直接实现；具体阈值和状态结构由本设计确定。

## 目的

把已有的“膀胱体积 → `interoception.urinaryUrgency` → `urinate`”接成可互动闭环：明显或强烈尿意可以提醒会话，但是否调用 `body_act { type: "urinate" }` 仍由会话决定。

## 当前基础

- `bladder.volumeMl` 已由水链更新，`interoception.urinaryUrgency` 已按 410 mL 设计锚点归一化到 0–100 mm。
- `body_act` 已支持 `urinate`，膀胱已有主动排尿和严格大于 600 mL 的非自主排空代理。
- 本设计实施前，`brainNotify` 只读饥饿/饱满；每会话只有一份 `lastLevel`，直接加入尿意会让不同信号互相压住。

## 目标

- `brainNotify` 读取 `interoception.hunger/fullness/urinaryUrgency`，缺失或非有限尿意按 0。
- 尿意 65 mm 进入明显档，发送 `context`；85 mm 进入强档，按现有 `wakeAtLevel=3` 发送 `wake`。
- 使用固定文本，不带膀胱数值、诊断结论或排尿指令。
- 每种信号分别记录滞回档位；冷却、每小时/每天配额仍按会话共享，每轮最多提醒一条。
- 先选最高档；同档优先级为 `urinary > fullness > hunger`。未被选中的信号不消耗自己的档位水位。
- `lastKind` 记录最近一次实际提醒的信号；`lastLevel` 保留下降闩锁（提醒时置为发送档位，未提醒时按当前档位只降不升），并作为旧会话迁移到 `levels` 的来源。新增每会话 `levels.hunger/fullness/urinary` 作为实际门控状态；`lastLevel/lastKind` 不是纯展示摘要。
- 旧会话状态按 `lastKind/lastLevel` 惰性迁移到 `levels`，不反推历史，不升存档 schemaVersion。
- 最近提交快照中 `bladder.voidedMl > 0`，或本轮 `io.actions` 已包含 `urinate` 时，抑制仍来自旧体感读数的尿意候选，避免排尿后补发过期提醒；其他体感候选不受影响。
- 单元测试覆盖阈值、跨信号独立、优先级、冷却、滞回、迁移和 JSON 安全；真实根清单覆盖“提醒 → 显式排尿 → 尿意回落”。

## 非目标

- 不修改膀胱 600 mL 非自主排空、主动排尿优先级、水账、根清单或工具 schema。
- 不自动调用 `urinate`，不降低非自主排空阈值，不建模失禁、逼尿肌、括约肌或临床尿急。
- 不新增口渴或不适提醒，不给 Gateway 通知增加 `kind` 字段，不改通知投递泵。
- 不改变饥饿/饱满的 65/85/40 mm 阈值、45 分钟冷却、每小时 2 次和每天 6 次配额。
- 不把离线测试称为真实 DSH 会话验收。

## 参数与证据边界

新增 `brainNotify.urinary.marked=65 mm` 和 `brainNotify.urinary.strong=85 mm`，均为 `status: "design"`、`source: null`，属于提醒 policy。它们不是人体排尿阈值或临床尿急界值。`resetBelow=40 mm` 只区分观测 0/1 档；用于门控的 `levels` 只保留 0/2/3，40–64 mm 的中间档按 0 计。同档重复需先低于已提醒档，升到更高档可直接提醒，这与既有饥饿/饱满行为一致。

所有脚本仍读轮初快照：`notify` 在 `interoception` 之上再晚一轮，因此尿意提醒相对轮初膀胱变化为两轮。真实根清单中，预置 410 mL 后第 1 轮只更新 `interoception.urinaryUrgency`，第 2 轮才发出尿意提醒。排尿后的过期尿意候选由最近提交的 `bladder.voidedMl` 和本轮 `urinate` 动作共同守卫，不为消除偏移而让同轮模块读取彼此的新输出。

## 补算限制

普通停机后的启动补算仍逐轮执行 `brainNotify` 并提交其状态；Gateway 只丢弃补算轮产生的通知。若补算轮触发提醒，`brainNotify` 仍会更新 `levels`、`lastSentAt` 和小时/天计数，即照常消耗冷却与配额，因此恢复后同一档位可能不再补发。这是既有 Gateway/通知架构的限制，本设计不修改补算或通知泵；若要补发或延后计数，应另立独立设计。

## 临时固定参考输入原则

后续器官若必须消费尚未建立的上游信号，可以用参数 JSON 中的固定参考值作为显式边界条件，但必须已有真实消费者，写清单位、来源、证据等级和未来替换点。只有上游按设计未接入时才能使用；上游已接入但数据异常时不得用固定值掩盖故障。本任务不需要新增此类参考值。

## 验收

- `npm test` 全部通过，包括既有空腹饥饿素和通知测试。
- 真实根清单中，预置膀胱 410 mL 后先出现尿意 `wake`，不发生自动排尿；显式提交 `urinate` 后只产生主动排尿，随后尿意回落且不重复提醒。
- 若在首次尿意提醒前已经提交 `urinate`，排尿轮不得补发旧尿意提醒；70→50→70 mm 的单元序列固定现有“低于明显档即重新武装”语义。
- 文档区分当前实现、历史验收和尚未完成的实机验证。
